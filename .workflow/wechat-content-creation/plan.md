# Workflow plan: Codex + Obsidian WeChat content creation

## Goal

设计一个本地优先、证据有边界、用户控制最终公开动作的微信公众号内容创作工作流，并准备成未来可放入GitHub的可复用项目。

## Success criteria

- 有清晰的Obsidian、Codex、GitHub和微信公众号分工；
- 有从来源到发布后的完整状态机；
- 有内容简报、主张台账、审校报告和上传清单模板；
- 有医学、隐私、版权和发布审批门；
- 有一个与当前UniPert-G2CP文章对应的本地示例；
- 本地预览检查通过；
- 未创建公开仓库、未commit、未push、未发布。

## Audience

具有临床、医学教学或科研背景，想用Codex和Obsidian稳定产出微信公众号内容的个人创作者。

## Constraints

- Obsidian库中的私人和未公开内容不能自动进入GitHub；
- 公众号准备与最终发布必须分开；
- AI生成的图像不承担精确中文、统计数字或医学标注；
- 医学内容必须区分事实、综合判断、假设和待核验项；
- 公开GitHub动作需要用户后续明确确认。

## Approval required

- 公开仓库创建或可见性变更；
- git commit、push、tag或Release；
- 公众号后台最终发布；
- 上传未公开研究资料或私人素材。

## Work packets

1. Discovery：读取主对话、侧边任务和当前工作区；
2. Domain：固定项目术语和边界；
3. Architecture：设计四层架构和状态机；
4. Templates：创建Obsidian、内容包和Codex提示词模板；
5. Example：接入UniPert-G2CP示例；
6. Verification：运行结构、链接和秘密扫描；
7. Release readiness：列出GitHub公开前未完成事项。

## Final deliverable

本地预览目录。等待用户确认后，再决定是否整理为独立仓库并进行GitHub操作。
