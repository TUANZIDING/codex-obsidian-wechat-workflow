# Obsidian 小白安全上手指南

这份指南说明如何把 Obsidian 接入本项目，以及什么时候可以使用第三方插件。

核心原则只有一句话：

> 插件可以帮助整理笔记，但不应该替你保管密码、登录公众号或自动发布文章。

## 先理解这套工作流

```text
Obsidian：保存来源和自己的知识
    ↓ 只选择本次任务需要的内容
Codex：提炼、写作、设计配图、检查边界
    ↓ 经过人工确认
微信公众号官方后台：本人登录、预览、发布
```

本项目不需要你把整个 Obsidian 库上传，也不需要把公众号密码、短信验证码、Cookie 或 API 密钥交给 Codex。

## 最安全的入门方式：先不安装第三方插件

小白第一次使用时，建议只使用 Obsidian 自带功能和本项目提供的 Markdown 模板：

1. 安装 Obsidian Desktop，并创建一个单独的“公众号工作流”库。
2. 不要直接把包含患者资料、未公开课题或私人日记的主库连接到公开项目。
3. 在库中创建 `来源笔记`、`选题简报` 和 `发布记录` 三类笔记。
4. 手动复制本次文章需要的来源、标题、 DOI、关键数字和限制性说明。
5. 将经过筛选的内容交给 Codex 生成草稿和检查清单。
6. 自己核对文章、配图版权、医学边界和公众号预览。
7. 自己在微信公众号官方后台登录、粘贴、预览和发布。

第三方插件不是本项目的必需条件。先用最小流程成功发布一篇文章，再考虑是否需要插件。

## 如何安装 Obsidian 社区插件

Obsidian 官方把社区插件视为第三方代码。安装前应先备份库，并逐个安装、逐个测试。

1. 打开 **Settings / 设置**。
2. 进入 **Community plugins / 社区插件**。
3. 如果仍处于 **Restricted mode / 受限模式**，只有在你确认信任插件作者后，才选择 **Turn on community plugins / 开启社区插件**。
4. 选择 **Browse / 浏览**，搜索插件名称。
5. 打开插件详情，检查作者、代码仓库、更新情况、说明文件和安全评分卡。
6. 选择 **Install / 安装**，安装完成后再选择 **Enable / 启用**。
7. 只安装一个插件，使用一段时间后再决定是否保留下一个。

官方说明：社区插件可以访问电脑文件、连接互联网，甚至安装其他程序；Obsidian 无法像浏览器权限系统那样可靠地把插件限制在某个文件夹内。因此，敏感资料库不应随意安装插件。

官方页面：

- [Community plugins](https://help.obsidian.md/Extending%2BObsidian/Community%2Bplugins)
- [Plugin security](https://help.obsidian.md/Extending%2BObsidian/Plugin%2Bsecurity)

## 插件怎么选择

| 需求 | 建议 | 是否必需 | 小白注意事项 |
|---|---|---:|---|
| 文章模板 | 先用本项目的 Markdown 模板；确有需要再选择模板类插件 | 否 | 模板插件不需要公众号密码 |
| 快速创建内容包 | 可选命令/快捷操作类插件 | 否 | 只允许它创建文件和插入模板，不要给它账号凭证 |
| 查询文章状态 | 可选查询/数据库视图类插件 | 否 | 先在测试库中运行，确认不会修改原始笔记 |
| 浏览器剪藏 | 可使用可信的剪藏工具 | 否 | 剪藏前删除患者信息、内部链接和未公开数据 |
| Git 自动同步 | 新手不建议默认启用 | 否 | 很容易把整个私人库、插件配置或附件推到远程仓库 |

本项目不要求安装某个特定插件。插件名称和安全状况会变化，安装前应以插件详情页和作者仓库为准，不要因为“别人推荐”就直接安装。

## 哪些信息必须由你手动填写或确认

### 可以由 Codex 帮你草拟，但必须由你确认

- 文章标题、目标读者和文章结构；
- 来源文章的 DOI、链接、作者、年份和关键数字；
- 哪些内容是原文直接显示，哪些是综合解释，哪些只是研究假设；
- 配图是否为原创生成图，是否使用了第三方图表；
- 是否包含医学建议、疗效承诺或容易被误解的表述；
- 微信公众号文章的最终标题、摘要、封面、作者署名和原文链接；
- 最终是否发布，以及发布后的链接和修改记录。

### 必须由你本人填写，不能交给 Codex

- Obsidian 库所在的本机路径；
- 微信公众号账号、密码、短信验证码、扫码登录、二次验证；
- 浏览器 Cookie、会话令牌、登录二维码；
- API key、Access Token、SSH 私钥、云服务密钥；
- 患者姓名、住院号、联系方式、影像原图和可识别病例信息；
- 未公开课题数据、审稿材料、内部会议文件和未发表结果；
- 个人身份证件、银行卡、支付信息和机构内部账号。

如果某个插件要求你把密码或 Token 直接粘贴到 Markdown 笔记、聊天窗口、截图或 Git 仓库中，应立即停止配置。先查看插件作者的官方说明，确认是否支持系统钥匙串或安全的本地凭证存储；本项目不会替你判断一个陌生插件是否安全。

## 凭证和隐私的“绝不提交”清单

下面这些内容不应出现在公开仓库、Obsidian 公共示例、Codex 提示词或截图中：

```text
.env、credentials.json、tokens.json、cookies.json
API key、Access Token、Bearer Token、SSH 私钥
微信扫码登录截图、Cookie、公众号后台截图
患者数据、病历号、手机号、身份证号
未公开论文、基金申请书、审稿意见、原始实验数据
```

本项目的 `.gitignore` 已包含 `.obsidian/`、密钥文件和私有资料目录的忽略规则。请注意：`.gitignore` 只能阻止“尚未提交”的文件进入 Git；如果秘密已经提交过，不能只靠添加 `.gitignore` 解决，还需要撤销凭证、清理历史并重新检查。

## 推荐的安全目录分工

```text
公众号工作流库/                  ← 可以用于日常创作
├── 00-收件箱/                   ← 剪藏后先人工清理
├── 01-来源笔记/                 ← DOI、链接、证据摘要
├── 02-选题简报/                 ← 读者、主张、文章路线
├── 03-内容包/                   ← 正文、主张台账、配图计划
├── 04-发布记录/                 ← 人工发布后的链接和反馈
└── private/                     ← 不进入公开仓库
```

不要把整个库直接拖进 GitHub。公开仓库只应包含已经检查过的模板、提示词、通用文档和明确允许公开的示例。

## 一次安全发布的人工检查点

在每个检查点都可以暂停，暂停不会损坏原始笔记。

| 检查点 | 你要确认什么 | Codex 可以做什么 |
|---|---|---|
| 来源 | DOI、链接、作者、年份和原文语境 | 整理字段、发现缺口 |
| 证据 | 直接证据、综合解释、假设是否分开 | 建立主张台账 |
| 隐私 | 没有患者信息、私有路径和内部材料 | 扫描明显风险，但不能代替人工判断 |
| 视觉 | 图片来源、版权、是否误用论文原图 | 生成无文字原创视觉方案 |
| 医学 | 没有过度推断、诊疗承诺或误导性表述 | 标记需要专家复核的句子 |
| 发布 | 标题、摘要、封面、作者、原文链接和最终预览 | 生成发布清单 |
| 复盘 | 发布链接、反馈和下次修改方向 | 整理发布记录 |

微信公众号登录、上传图片、手机验证、预览和点击“发表”必须由账号所有者在官方后台完成。本项目不保存登录状态，也不提供绕过验证的方式。

## 出现问题时怎么撤销

1. 插件行为异常：在 **Settings → Community plugins → Installed plugins** 中关闭插件。
2. 不确定插件是否可信：重新开启 **Restricted mode**，插件会被忽略，但不会自动删除。
3. 笔记被改坏：先停止同步和自动化，再从本地备份或版本历史恢复。
4. 密码或 Token 疑似暴露：立即在对应服务中撤销并重新生成，不要只删除聊天记录。
5. 误推送私人文件：先将仓库设为私有或暂停 Pages，再清理 Git 历史并轮换所有凭证。

## 给小白的最短路径

```text
创建独立工作流库
  → 不安装插件也能完成第一篇
  → 只安装一个可信插件
  → 只把本次文章素材交给 Codex
  → 人工完成证据、隐私、版权和医学检查
  → 本人登录微信公众号后台
  → 手动预览、发布、记录反馈
```

如果一个步骤要求你提供密码、Cookie、验证码或私人库的全部内容，说明它已经超出了本项目的安全边界。
