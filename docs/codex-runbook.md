# Codex操作手册

## 使用原则

每次任务都先说明四件事：

1. 输入文件和来源范围；
2. 目标受众与发布渠道；
3. 允许修改的范围；
4. 本轮需要停在哪个审批门。

不要把“帮我写一篇”理解成可以自动公开发布。内容准备、质量审校、用户批准和公开发布是四个不同动作。

## 推荐的六个Codex工作包

### Packet 01：来源分流

读取Obsidian来源笔记，提取事实、数字、模型、限制和缺口，创建主张台账。

### Packet 02：内容简报

根据目标读者和选题目标，确定标题、开头问题、段落顺序、文章边界和互动问题。

### Packet 03：正文写作

只使用已经标记为可用的来源；把直接证据、综合判断和假设分开；保留免责声明。

### Packet 04：视觉规划

建立图片清单、图片任务、尺寸、文字限制、来源和生成提示词。若要生成图片，先明确是否允许AI生成。

### Packet 05：审校

检查主张、医学边界、隐私、版权、链接、图片路径和目标读者可读性。

### Packet 06：上传打包

生成一个状态为 `approved` 或 `preview` 的内容包，给出标题、正文、图片顺序和人工操作清单，不点击最终发布。

## 推荐提示词骨架

```text
任务：把指定Obsidian来源整理成微信公众号文章。
受众：<青年医生 / 医学教师 / 科研人员 / 其他>
来源范围：<明确文件或笔记>
文章主张：<一句话>
必须保留：<数字、限制、来源、免责声明>
禁止推断：<未被来源支持的机制、疗效、临床结论>
图片要求：<封面 / 结构图 / 案例图；是否允许Image Gen>
审批门：完成到<初稿 / QA / 可上传包>，不要发布。
输出：<文件路径和格式>
```

## 典型使用顺序

```text
先读来源 → 再做简报 → 用户确认角度 → 写初稿 → 生成配图 → 逐条审校 → 用户批准 → 生成上传包
```
