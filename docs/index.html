THE DRIVE / 01—04

每一步都有自己的码线，也有自己的责任边界。

内容包像一个沿球场推进的球：可以继续推进，但不能跳过证据、医学、隐私、版权和人工批准。

PLAYBOOK / CONTENT CREATION

从来源笔记到受控发布端

GOAL LINE = USER APPROVAL
01 / SOURCE

Obsidian

保存来源、研究笔记、临床问题和可长期复用的知识。

02 / PLAY

Codex

把素材整理成读者问题、文章结构、主张台账和配图计划。

03 / REVIEW

QA + 人工确认

核查证据直接性、医学表述、隐私、版权和发布边界。

04 / RELEASE

微信公众号

只把通过检查并经作者确认的内容包，手动带入发布后台。

CONTROL GATES / SAFETY

视觉可以有推进感，证据边界必须保持安静而清楚。

工作流的目标不是让模型替代作者，而是让每个判断都能被追溯、复核和暂停。

↗

证据分层

区分直接证据、综合解释、合理假设和尚未核实的内容，不用流畅措辞掩盖缺口。

⌁

本地优先

私人 Obsidian 库、未公开研究资料、患者信息和凭证不进入公开仓库。

⚑

人工复核

医学边界、作者署名、版权处理和最终发布都保留在作者可以停止的控制点。

□

可回写

发布链接、读者反馈和修改意见回到 Obsidian，形成下一轮创作的可检索记录。

QUICK START / 04 STEPS

从一篇笔记开始，不必先搭建一个大平台。

预览版把一次创作拆成几个小而可检查的内容包，适合先用真实需求验证，再逐步扩展模板和自动化。

选定一条来源笔记明确主题、来源和目标读者。
运行来源分诊提示词建立主张台账，标记证据状态和缺口。
形成文章与视觉计划正文、图片、流程图和版权记录分开管理。
通过检查后人工发布把反馈写回 Obsidian，保留发布记录。
