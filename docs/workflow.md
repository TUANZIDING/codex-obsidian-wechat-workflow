# 全流程：从Obsidian素材到微信公众号发布

## 状态机

```text
inbox
  → sourced
  → briefed
  → outlined
  → drafted
  → visualized
  → qa_failed ↔ drafted / visualized
  → qa_passed
  → approved
  → packaged
  → uploaded
  → published
  → reviewed
```

允许任何阶段进入 `blocked`，但不能把缺失来源或等待用户确认默认为完成。

## Phase 0：建立选题入口

在Obsidian中先保存一个来源笔记或问题笔记。最少要回答：

- 这个内容来自哪里？
- 面向谁？
- 读者遇到什么具体问题？
- 希望读者读完后做什么？
- 哪些内容尚未核验？

对于论文内容，保留标题、作者、期刊、日期、DOI、原文链接和研究边界。

## Phase 1：来源分流

Codex先做来源分流，不直接写宣传文案：

- `direct`：来源直接支持；
- `synthesis`：多条来源组合后的概括；
- `hypothesis`：可用于提出研究问题，但未被当前来源证实；
- `unverified`：需要补充检索或人工确认；
- `not_applicable`：不适合放入当前文章。

## Phase 2：内容简报

先冻结：

- 标题候选；
- 目标读者；
- 读者痛点；
- 一句话主张；
- 文章主线；
- 文章不写什么；
- 医学、版权和隐私边界。

推荐公众号叙事顺序：

```text
具体痛点 → 为什么会这样 → 你的方法 / 论文方法 → 结果或作品 → 局限 → 项目入口 / 互动问题
```

## Phase 3：写作

正文优先采用短段落、小标题和可解释的术语。论文解读不应把摘要逐段翻译，而应让读者理解：

- 研究问题是什么；
- 以往为什么难；
- 这项工作改变了哪一步；
- 证据支持到哪一层；
- 下一步还需要什么验证。

## Phase 4：视觉

每张图先绑定一个阅读任务，而不是先生成装饰图：

- 封面：让读者一眼知道主题；
- 结构图：解释复杂流程；
- 证据图：帮助读者理解数据关系；
- 案例图：连接抽象方法与具体问题；
- 边界图：提醒模型和研究的限制。

图像生成尽量不放中文、统计数字、公式和精确解剖标注；这些内容留在可编辑正文、HTML或PPT中。

## Phase 5：质量审校

至少检查五条线：

1. 来源：每个关键主张能否回到来源；
2. 科学：是否把相关性、预测、机制线索写成了因果证明；
3. 医学：是否存在患者特异性建议或临床操作误导；
4. 版权：图片、原文、数据、链接和代码是否有清楚出处；
5. 隐私：是否包含患者、账号、私有库或未公开数据。

## Phase 6：用户确认与上传包

只有用户明确确认后，状态才能从 `qa_passed` 进入 `approved`。上传包包括：

- 标题；
- 作者；
- 摘要或开头；
- 正文；
- 封面图；
- 正文图片顺序；
- 阅读原文链接；
- 上传前核对清单。

`approved` 不等于 `uploaded`，`uploaded` 不等于 `published`。

## Phase 7：发布后复盘

把公开链接、发布时间、实际修改、读者反馈和下一篇选题写回Obsidian。重点记录：

- 哪类读者有真实回应；
- 哪一段被收藏或转发；
- 读者提出了什么具体问题；
- 你实际花了多少时间；
- 哪些部分可以模板化；
- 哪些内容不应继续扩张。
